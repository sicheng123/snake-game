# 贪吃蛇游戏设计文档

## 概述

使用 Python 和 `pygame` 库开发的经典贪吃蛇游戏。包含多种食物类型、障碍物、速度递增、暂停功能、最高分持久化存储，以及基于场景的导航系统（主菜单、游戏中、暂停、游戏结束）。

## 环境要求

- Python 3.8+
- `pygame` 库（通过 `pip install pygame` 安装）

## 文件结构

```
snake_game/
├── main.py           # 入口：初始化 pygame，驱动主循环
├── config.py          # 常量：窗口尺寸、颜色、速度、网格配置
├── game_state.py      # 核心模型：蛇的身体、方向、碰撞检测、分数
├── food.py            # 食物：类型定义、生成逻辑、计时器
├── obstacles.py       # 障碍物：位置管理、碰撞检测
├── renderer.py        # 视图：所有绘制（蛇、食物、障碍物、界面文字、菜单）
├── scenes.py          # 场景管理：菜单/游戏/暂停/结束 状态机
└── highscore.py       # 最高分：JSON 文件读写
```

## 架构设计

### 设计原则：单一职责

每个文件只负责一件事。改食物行为只动 `food.py`，改渲染效果只动 `renderer.py`。各模块互不干扰。

打个比方：就像盖房子，你不会把水管图、电路图、设计图全画在一张纸上。分开画的好处是——想改电路的时候不用翻整张图纸，也不怕不小心把水管给改了。

### 数据流向

```
按键事件 → 场景管理器 → 游戏状态更新 → 渲染器绘制 → 屏幕显示
```

- 按键事件在主循环中捕获，交给当前活跃的场景处理
- 场景处理器调用 `GameState` 的方法来修改状态
- `Renderer`（渲染器）是**只读的**：它只取数据画出来，绝不修改状态
- 没有任何模块导入 `main.py`——依赖关系单向流动

### 主循环

```
while 游戏没退出:
    1. 处理事件（按键、关闭窗口）
    2. 当前场景处理输入 → 更新游戏状态
    3. 渲染器绘制当前帧（背景、蛇、食物、障碍物、界面）
    4. 时钟控制帧率和蛇的移动速度
```

整个游戏就是一个死循环，每秒跑 N 次。每一帧做三件事：**输入 → 更新 → 渲染**，循环往复。

## 场景系统

`scenes.py` 中管理四个场景，像一个"页面路由器"，根据当前场景决定显示什么、响应什么按键：

| 场景 | 显示内容 | 可用操作 |
|------|---------|---------|
| 主菜单 | 标题 + "按回车开始游戏" | 回车 → 进入游戏 |
| 游戏中 | 蛇 + 食物 + 障碍物 + 分数 | 方向键/WASD 移动 + 空格暂停 |
| 暂停 | 游戏画面定格 + "暂停中"遮罩 | 空格 → 继续游戏 |
| 游戏结束 | "游戏结束" + 本局分数 + 最高分 | 回车 → 回到主菜单 |

场景之间的切换是单向的（不能从菜单直接跳到暂停）。每局新游戏开始时，场景管理器创建一个全新的 `GameState` 实例。

## 游戏状态 (`game_state.py`)

### 蛇的数据结构

蛇的身体用一个**列表**表示，列表中每个元素是一个 `(x, y)` 坐标，代表蛇身体的每一节，**头部在前**：

```
蛇向右移动时: [(5,3), (4,3), (3,3), (2,3)]
              头 →                 ← 尾
```

移动由**方向向量**驱动：

| 方向 | 向量 (dx, dy) |
|------|--------------|
| 上   | (0, -1)       |
| 下   | (0, 1)        |
| 左   | (-1, 0)       |
| 右   | (1, 0)        |

每一步移动：新头部 = 旧头部坐标 + 方向向量。在列表前端插入新头部，删除尾部。

**吃到食物时**：只在头部插入新坐标，不删除尾部 → 蛇变长一格。

### 防反向规则

如果玩家按下与当前方向完全相反的键，输入被忽略。例如蛇正在向右走，按左键无效——蛇不能原地掉头。

### 碰撞检测

每一步移动后检查三种死亡条件：

| 碰撞类型 | 检测条件 | 结果 |
|---------|---------|------|
| 撞墙 | 头部坐标超出网格边界 | 游戏结束 |
| 撞自己 | 头部坐标与身体任一节重合 | 游戏结束 |
| 撞障碍物 | 头部坐标与任一障碍物坐标重合 | 游戏结束 |

碰撞检测返回布尔值：`True` = 存活继续，`False` = 游戏结束。

### 速度递增

- 初始速度：每步 150 毫秒
- 每吃 5 个食物：间隔减少 10 毫秒
- 最快速度：每步 50 毫秒（设上限，防止快到无法操作）

### 计分规则

- 普通食物：+10 分
- 加速食物：+5 分
- 减速食物：+5 分

## 食物系统 (`food.py`)

三种食物类型，各有不同的属性：

| 食物类型 | 颜色 | 效果 | 出现概率 | 持续时间 |
|---------|------|------|---------|---------|
| 普通食物 | 绿色 | +10 分，蛇变长 1 格 | 70% | 永久存在 |
| 加速食物 | 黄色 | +5 分，移动间隔 -30 毫秒 | 15% | 8 秒后消失 |
| 减速食物 | 蓝色 | +5 分，移动间隔 +30 毫秒 | 15% | 8 秒后消失 |

- 同一时间只存在一个食物
- 食物在随机空格子处生成（不能生成在蛇身上，也不能生成在障碍物上）
- 加速/减速效果持续 8 秒，到期后速度恢复到当前等级的基础值
- 限时食物会**逐渐缩小**，给玩家即将消失的视觉提示

## 障碍物 (`obstacles.py`)

- 障碍物是网格上的静态方块
- 每局开始时生成 N 个障碍物，放置在随机空格子上（不能与蛇的初始位置重叠，障碍物之间也不能重叠）
- 数量：可配置，默认 8 个
- 碰到任一障碍物 = 游戏结束

## 渲染器 (`renderer.py`)

### 网格系统

- 窗口大小：800×600 像素
- 网格单元格：20×20 像素
- 可玩区域：40×30 格

### 绘制顺序（从下到上）

1. 背景填充（黑色）
2. 网格线（深灰色，可选）
3. 障碍物（暗红色方块）
4. 食物（根据类型显示不同颜色的圆形/圆角方块）
5. 蛇身（绿色方块，每节之间留细微缝隙）
6. 蛇头（比蛇身稍亮的绿色，可选画眼睛）
7. 分数文字（左上角，白色）
8. 菜单/暂停/结束的遮罩层（半透明背景 + 居中文字）

### 界面文字

- 主菜单：大号标题 "贪吃蛇"，小号提示 "按回车开始游戏"
- 暂停：半透明深色遮罩 + "暂停中" + "按空格继续"
- 游戏结束："游戏结束" + 本局分数 + 最高分 + "按回车返回菜单"

## 操作控制

| 按键 | 功能 |
|------|------|
| ↑ / W | 向上移动 |
| ↓ / S | 向下移动 |
| ← / A | 向左移动 |
| → / D | 向右移动 |
| 空格 | 暂停 / 继续 |
| 回车 | 确认（菜单、游戏结束） |
| Esc | 退出游戏 |

## 最高分持久化 (`highscore.py`)

- 存储位置：`~/.snake_game_highscore.json`
- 存储格式：`{"score": 42}`
- `load_highscore()` 读取文件（文件不存在或损坏时返回 0）
- `save_highscore(score)` 仅在新分数大于已存储分数时才写入
- 对文件不存在、JSON 格式损坏等情况做容错处理

## 错误处理

- 最高分文件不存在 → 默认返回 0，首次保存时自动创建
- 最高分文件损坏 → 重置为 0，用有效数据覆盖
- pygame 初始化失败 → 打印错误信息并以退出码 1 退出
- 食物计时器逻辑使用 try/except 防止边界情况导致的崩溃

## 测试策略

- 手动试玩，检验游戏手感和平衡性
- 验证四个场景之间的切换是否正常
- 验证最高分在重启游戏后是否正确保留
- 验证食物不会生成在蛇身或障碍物上
- 验证反向按键被正确拦截
- 验证速度不会降到最低上限以下（不会快得离谱）
