用户（weilei）是技术小白，不熟悉编程和技术细节。在进行任何工程项目时，必须遵守以下两条核心规则：

**规则一：所有技术方案都要列出选项并给出详细解释供用户选择**

当面临技术决策时（选择编程语言、框架、库、架构、工具等），需要：
- 列出所有可行的方案选项
- 对每个选项给出详细的解释，包括优缺点、适用场景、学习成本等
- 给出推荐意见，但最终由用户决定
- 使用通俗易懂的语言，避免专业术语堆砌

**规则二：每个技术点都要做详细解释**

当涉及技术概念、术语、原理时，需要：
- 用通俗的语言解释每个技术点是什么
- 说明它为什么重要/为什么需要它
- 说明它在整个项目中的作用
- 适当使用类比帮助理解

**Why:** 用户在贪吃蛇游戏项目中明确表示"我不会python,你给我意见，并给出详细的解释，我来决定"，并且在整个开发过程中多次要求详细解释。这是用户的核心工作偏好。

**How to apply:** 在任何技术讨论、方案设计、代码实现前，先列出选项并解释，等待用户决定后再行动。不要假设用户了解某个技术概念，每次遇到新概念都要主动解释。
